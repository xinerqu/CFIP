# CFIP优选

> **Cloudflare 优选 IP 测速 —— 先验证，再测速，测完直接回写**
>
> 作者：**卡马尔冰雨**

给 Cloudflare 优选 IP 做的测速工具。Windows 绿色版，解压双击就能用。

---

## 它和别的优选工具差在哪

| | 传统优选工具 | CFIP优选 |
|---|---|---|
| 会不会混进 1034 的死 IP | 会，还给个漂亮的速度 | 不会，第一个阶段就剔除 |
| 带宽口径 | 单流，被 BDP 卡死，系统性低估 | 多流并行聚合，1~16 可配 |
| 结果稳定性 | 单次测量，名次随机颠倒 | 重复测量取中位数，波动大主动提示 |
| 覆盖回源段 | 不覆盖 | 覆盖（走你自己的 Worker） |
| 延迟口径 | TCP / TLS 握手 | **generate_204，和 clash 面板同口径**（热连接） |
| 测完还要手动粘 IP | 是 | 不用，可直接写回 edgetunnel，锁定项不动 |
| 运行环境 | 常要 PowerShell 7 / Python / curl | 单 exe + 两个 DLL |

两个根本问题，它是这么解决的：

**一、绝大多数工具不校验「这个 IP 服不服务你的域名」。** CF 边缘 IP 全球几百个机房，你连哪个都能握手成功，但只有部分机房承载你的 zone。发到不承载的机房，CF 在**进 Worker 之前**就回 `403 / error code: 1034`。传统工具把这张错误页的下发速度算成「速度」，报给你一个漂亮数字，你拿去用一个字节都过不去。实测 20 个候选里 7 个真的服务、13 个是 1034。

**二、它测的不是你真实用起来的速度。** 你的流量走三段：

```
你的电脑 ──①──▶ CF 边缘 ──②──▶ 你的 Worker ──③──▶ YouTube / GitHub
```

传统工具拿 jsdelivr / unpkg 上的静态大文件测——那是 CF 自家的 CDN 静态通道，几乎零距离、有缓存、独立出口。**你刷 YouTube 走的是 ③ 那段 Worker fetch 出口，限流更严。** 所以会出现「工具报 200Mbps，实际看视频卡」——不是算错了，是压根没测那一段。

本程序在你自己的 Worker 上加一个端点，让测速请求真的穿过 ③ 再回来。这样测出来的数字才包含全链路。

## 快速开始

1. 到本仓库右侧 **Releases** 下载 `cfip_gui.zip`，解压（共 5 个文件，缺 DLL 会报 `0xC0000135`）
2. 双击 `cfip_gui.exe`

## 给 Worker 加测速端点

没有端点也能用，只是「测速方式」里只有内置静态源可选，测不到回源那一段。

**做法：菜单 → 工具 → 给 Worker 加测速端点…**

1. 先把 Worker 代码弄到本地：CF 后台 → Workers & Pages → 你的 Worker → 编辑代码 → 全选复制 → 粘到记事本存成任意文件（`.js` `.txt` 都行，**记事本存成 ANSI 也没关系，程序会自动纠正编码**）
2. 用上面的菜单项选这个文件，程序在同目录生成 `原名_已注入` + 原扩展名，**原文件一个字节不改**
3. 打开新文件全选复制 → CF 控制台全选删除再粘贴 → Deploy
4. 验证：`curl "https://你的域名/__speed?mb=1" -o NUL -D -` 应该看到 `X-Speed-Bytes` 和 `X-Upstream-Mode` 两个头

命令行等价：`cfip_gui.exe --inject C:\path\_worker.js`

**片段装了哪两个端点**

| 端点 | 用途 | 返回头 |
|---|---|---|
| `/__speed?mb=N` | 测速度，回源 Google 视频 CDN 大文件 | `X-Speed-Bytes` / `X-Upstream-Mode` / `X-Upstream-Landed` |
| `/__gen204` | 测延迟，Worker 内部 `fetch('gstatic.com/generate_204')` | `X-G204-Status` / `X-Upstream-Ms` |

`/__speed` 的 URL 参数：`mb=N`（1~200，默认 50）、`u=dl`（换 Google 静态 CDN）、`n=0/1/2`（轮转视频 CDN 源）、`token=`（只有设了 `SPEED_TOKEN` 才要）。

**额度**：一次测速 = 一次 Worker 请求。免费版每天 10 万次，跑 20 个 IP × 重复 3 次 = 60 次，占 0.06%。

**升级须知**

| 你从哪版来 | 要重装端点吗 |
|---|---|
| v1.9 及更早 | **要**。1.9 的片段没有 `/__gen204` |
| v2.0 / v2.1 | 不用，片段一个字节没变 |

没重装也不会崩：程序请求 `/__gen204` 会落到 edgetunnel 的 nginx 伪装页（200 + 613 字节），程序发现响应头里没有 `X-G204-Status` 就判定端点不存在，**自动回落 TLS 口径**并提示你。判定列会写：`Worker 没有 /__gen204 端点（用的是 1.9 及以前的片段）`。

## 测完直接回写 edgetunnel

测出来的结果可以直接写回你 Worker 的 `ADD.txt`，替换那串自定义 IP，不用再开网页一条条粘。

**用法**

1. 第四行勾上 **「测速后回写」**
2. 点旁边的 **「回写列表…」**，填 Worker 域名和管理密码，点「读取」
3. 列表里就是 edgetunnel 现在的 IP。**双击任意一行就地编辑**，改完回车
4. 不想被覆盖的行**点左侧勾选框** —— 勾选即锁定，立刻生效
5. 关窗，正常跑一次测速。结束后状态栏显示「回写成功：锁定 N 条原样保留，去掉旧 M 条，写入新 K 条」

**列表窗口操作**

| 操作 | 怎么做 |
|---|---|
| 改一行 | 双击，就地变输入框，回车 |
| 删一行 | 双击后清空，回车 |
| 删多行 | Ctrl / Shift 多选，按 `Delete` |
| 加一行 | 点「添加一行」，末尾输入，回车 |
| 锁定 / 解锁 | 点左侧勾选框 |
| 立刻写回 | 点「保存到 edgetunnel」 |

**几件事要知道**

- 写入是**整文件覆盖**：程序先读全量 → 本地合并 → 整体写回 → 再回读校验字节数
- 写入前自动备份到 `ADD_备份.txt`；服务器返回非 `success` 就报错，不动线上
- 密码用 Windows DPAPI 加密存在本机 `cfip_edg.dat`，只有同一个 Windows 账户能解
- 锁定状态存在 `cfip_locks.txt`，按整行文本比对——那行内容不变就一直被保护
- **一条都不锁时，下次结果会整体替换列表**。没标记就等于允许覆盖，这是设计如此
- 回写格式固定 `ip:端口#国家序号 延迟ms 速度Mbps`（如 `104.18.39.119:443#SG1 207ms 224.58Mbps`），**不受输出模板影响**——edgetunnel 靠 `#` 后面的名字显示在你的代理工具里，格式乱了不好认
- 条数上限默认 20（`--addmax`）

## 命令行

GUI 的功能命令行都有，`cfip_gui.exe --cli --help` 打印完整说明。

```bat
:: 测文件里的 IP
cfip_gui.exe --cli --domain abc.example.com --ipfile ips.txt

:: 从 IP 库随机取 30 个，全用 8443
cfip_gui.exe --cli --domain abc.example.com --iplib 1 --ipcount 30 --libport 8443

:: 测真实路径（走自己的 Worker 回源）
cfip_gui.exe --cli --domain abc.example.com --ipfile ips.txt --realpath ^
  --threads 1 --streams 2 --repeat 5 --timelimit 20 --timeout 5000

:: 只留延迟<800ms 且速度>2Mbps
cfip_gui.exe --cli --domain abc.example.com --ipfile ips.txt ^
  --maxdelay 800 --minspeed 2 --sort delay

:: 先看看 edgetunnel 现在有哪些 IP（只读）
cfip_gui.exe --cli --adddump --addurl https://abc.example.com --addpass 你的密码

:: 测完直接回写
cfip_gui.exe --cli --domain abc.example.com --ipfile ips.txt --realpath ^
  --threads 1 --streams 2 --repeat 3 --timelimit 15 --timeout 5000 ^
  --addwrite --addurl https://abc.example.com --addpass 你的密码 --addmax 15
```

不给 `--addpass` 时 `--addwrite` 只打印候选行，**不会去连服务器**。

## 用法建议

**先摸底再定论。** 先用内置源快速筛：
担心消耗请求数，先内置源
几十秒筛掉大部分差 IP。再测真实路径。

**四条必须记住的**

- **测排序时 `--threads 1`。** 多个 IP 同时测会互相抢本机带宽，实测全从 140~225Mbps 掉到 102~157Mbps，比例还各不相同，名次直接乱。
- **`--repeat 3` 不能省。** 相邻 IP 差距只有 3%~8%，单次测量基本靠运气。
- **真实路径的绝对值不要和静态源比。** 差两个数量级是正常的，它们测的不是同一段。

**并行与并发的区别**：`--threads` 是同时测几个 IP（测排序必须 1）；`--streams` 是每个 IP 开几条连接（保持 4 左右，模拟实际拉流并发度）。单条 TCP 连接受带宽时延积限制，跨太平洋 RTT 150ms 时单流只能跑 142Mbps，4 流能到 320Mbps——不开多流会系统性低估，还会导致名次颠倒。

## 常见问题

**Q：双击报 `0xC0000135` / 提示缺 DLL？**
缺 OpenSSL 运行库。把 `libssl-3-x64.dll` 和 `libcrypto-3-x64.dll` 放到 exe 同目录。

**Q：全部 IP 都显示「该IP不服务此域名(CF 1034)」？**
两种可能：域名填错，或这批 IP 的机房不在你 zone 的分配范围里。核对域名无误就换个 IP 库重试。

**Q：判定列显示「Worker 没加 /__speed 端点(613B页面)」？**
程序从响应头上认出来这路径回的是网页不是端点。检查三处：①片段粘了没 Deploy；②「测速路径」框里残留了别的路径，清空即可；③用 Pages 的话 `_worker.js` 要放项目根目录并重新部署。

为什么不用 `Content-Length` 判断？因为 CF 在 `TransformStream` 之后会强制改 `chunked`，那个头被丢掉。

**Q：真实路径全部「上游短读」？**
上游给了一点数据就断。换一条回源线路（高级里的下拉），`--upstream 3`（Google 静态 CDN）更稳。实测 gvt1 在部分机房会短读。

**Q：开着梯子能不能测出真实值？**

| 形态 | 能吗 | 原因 |
|---|---|---|
| 纯直连 | ✅ | 没有拦截 |
| 只有系统代理 | ✅ | 本程序用原始 socket，不读系统代理设置 |
| TUN 虚拟网卡 | ❌ | TUN 接管全部流量 |
| 路由器上的代理 | ❌ | 拦截在电脑之外，本机看不到 |

程序会自动检测并提示（两个信号：黑洞地址是否秒连判断本机 TUN；家宽出口 IP 与测速路径出口 IP 是否一致判断网关级代理）。**只检测不绕过**——代理跑在路由器上时本机做什么都没用，而关代理只是点一下的事。

**Q：结果里有些 IP 显示 `XX`？**
那个 IP 的响应头里没有可解析的 `CF-RAY`。程序用 `XX` 占位。

**Q：结果文件编码？**
UTF-8 无 BOM。记事本可能显示乱码，用 VS Code / Notepad++ 打开。

### v2.1

- **延迟改热连接测量**：原来每个 IP 新建 TCP + 新建 TLS，白算 2~6 个 RTT。现在「建一次连接 → 发预热请求（计时丢弃）→ 同一条连接上发正式请求并计时」。同一 IP 从 1142ms 降到 **207ms**，和 clash 实测的 185~191ms 同量级

- `fetch_one` 补 `204 / 304 / contentLen == 0` 时头收完即返回（`204 No Content` 没有 `Content-Length`，keep-alive 下对端也不关，不补会等到超时）

### v2.0

- 新增第 4 种延迟口径 **generate_204（同 clash）** 并设为默认：Worker 内部 `fetch('gstatic.com/generate_204')` 再回 204，和 clash / mihomo / Shadowrocket 走完全相同的路径
- Worker 片段新增 `/__gen204` 端点，返回 `X-G204-Status` / `X-Upstream-Ms`。实测回源那一段只多花 18~47ms
- CLI 新增 `--delaymode w204`（别名 `gen204` / `gstatic`）
- 「TCP 连接」口径加失真警告：有网关级代理时 SYN 被本地代答，测出来是 0ms 假数字

### v1.9

- **一键注入不再被编码搞坏**：读 `_worker.js` 时先看 BOM，没有就做 UTF-8 合法性校验，不通过就判定 ANSI/GBK 并**自动转成 UTF-8** 再注入。背景是 edgetunnel 里大量中文变量名（`缓存SOCKS5白名单` 等），用记事本存成 ANSI 后直接注入照样部署失败
- 注入提示会告诉你原文件是什么编码、已转成 UTF-8
- 识别文件末尾那段 4714 KB 的希伯来文块注释（占全文件 93%，对运行无影响），提示里报大小和占比
- 注入不再强制 `.js`，`.txt` 也能选，输出扩展名跟着输入走

### v1.8

- **新增一键注入**：选你的 `_worker.js`，程序在 `async fetch(request, env, ctx) {` 下一行插入整段端点，同目录生成 `原名_已注入.js`，**原文件不改**。CLI `--inject` / `--injectout`
- 以前要自己在几万行代码里数行号、腾空行、整块粘，粘歪一格就 `Unexpected token 'else'`
- 注入前两项检查：已有端点就拒绝；找不到 `async fetch(` 就拒绝并告诉你怎么回事
- 新增「程序怎么判断端点没加」判定表

### v1.7

- **新增代理检测**（只检测不绕过）：信号 A 用 RFC 5737 保留地址探本机是否被 TUN 接管（真直连必超时，TUN 会毫秒级代答 SYN）；信号 B 对比「家宽真实出口」和「测速路径出口」两个 IP，不一致就是网关级代理
- 开着代理时测出来的可能是「IP ↔ 代理节点 ↔ 你」的综合值，甚至把黑洞 IP 测成 100Mbps
- 早期试过用 `IP_UNICAST_IF` 绑网卡绕开本机 TUN，有效但代理在路由器上时完全无效，所以只保留检测
- 新增「Worker 端点存在性」判定，把「端点没加」和「上游短读」区分开

### v1.6
